# Deploying to Render + MongoDB Atlas

The database is a free **MongoDB Atlas** M0 cluster either way. For the app itself you pick one of two
shapes:

| | **Option A — split, no Docker** | **Option B — one Docker service** |
|---|---|---|
| Services | API (Node) + static site (CDN) | one web service |
| Blueprint | `render.yaml` | `render.docker.yaml` |
| Front end | served from Render's CDN, never sleeps | sleeps with the API on the free plan |
| Env vars | `VITE_API_URL` on the site, `CLIENT_ORIGIN` on the API | same-origin, nothing to wire |
| Good for | hosting the front end anywhere (Render, Netlify, Vercel, Cloudflare Pages) | fewest moving parts |

Option A is the default in this repo. Do step 1, then either step 2A or step 2B.

The front end reads its API origin from **`VITE_API_URL`** at *build* time (Vite inlines it; there is no
runtime config file). Leave it blank and the app calls its own origin — which is what local dev wants, since
Vite proxies `/api` and `/uploads` to port 5050, and what Option B wants too. See `client/.env.example`.

---

## 1. Database — MongoDB Atlas (≈5 minutes)

1. Sign up at **https://www.mongodb.com/cloud/atlas/register**.
2. **Create a cluster** → *M0 Free*. Pick the region nearest your visitors (Mumbai `ap-south-1` or
   Singapore `ap-southeast-1` for Bangladesh).
3. **Database Access** → *Add New Database User*:
   - Authentication: Password
   - Username: `portfolio`
   - Password: click *Autogenerate* and **copy it** — you need it in step 5.
   - Role: *Read and write to any database*
4. **Network Access** → *Add IP Address* → **Allow access from anywhere** (`0.0.0.0/0`).
   Render's free plan has no fixed outbound IP, so an allowlist of specific IPs will block it.
5. **Clusters → Connect → Drivers** and copy the connection string. It looks like:

   ```
   mongodb+srv://portfolio:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```

   Replace `<password>` with the password from step 3, and insert the database name before the `?`:

   ```
   mongodb+srv://portfolio:YOUR_PASSWORD@cluster0.xxxxx.mongodb.net/faysal_portfolio?retryWrites=true&w=majority
   ```

   Keep this string — it is `MONGODB_URI` below. If the password contains `@ : / ? # [ ] %`, URL-encode it.

## 2A. Split deploy, no Docker (≈10 minutes)

Two Render services from one blueprint. Each one's URL goes into the other's env vars, so this is a
**two-pass deploy**: create them, then paste the two URLs and redeploy.

1. Sign up at **https://render.com** and connect your GitHub account.
2. **New → Blueprint** → the `mdabufaysaljoy/portfolio` repo. Render reads `render.yaml` and proposes:
   - `faysal-portfolio-api` — Node web service, free plan, `npm install` / `npm run start`
   - `faysal-portfolio-web` — static site, `npm run build` published from `client/dist`
3. Fill in the variables Render asks for. Leave the two URL ones **blank for now**:

   | Service | Variable | Value |
   |---|---|---|
   | api | `MONGODB_URI` | the Atlas string from step 1.5 |
   | api | `ADMIN_EMAIL` | the email you want to sign in with |
   | api | `ADMIN_PASSWORD` | a strong password you choose now (**not** the demo one) |
   | api | `CLIENT_ORIGIN` | *(blank — step 5)* |
   | web | `VITE_API_URL` | *(blank — step 5)* |

   `JWT_SECRET` is generated by Render. `NODE_ENV`, `JWT_EXPIRES_IN` and `SERVE_CLIENT=false` come from
   `render.yaml`; `PORT` is injected by Render.
4. **Apply**. Both build. The site will show a load error until step 5 — that is expected.
5. Copy each service's URL from its dashboard page, then set the pair (scheme included, **no trailing
   slash**):

   | Service | Variable | Value |
   |---|---|---|
   | api | `CLIENT_ORIGIN` | `https://faysal-portfolio-web.onrender.com` |
   | web | `VITE_API_URL` | `https://faysal-portfolio-api.onrender.com` |

   Saving an env var redeploys that service. `VITE_API_URL` is compiled into the bundle, so the site **must**
   rebuild after you set it — Render does that automatically on save.
6. Verify, then sign in at `https://faysal-portfolio-web.onrender.com/admin`:

   ```bash
   curl https://faysal-portfolio-api.onrender.com/api/health
   # {"data":{"ok":true,"driver":"mongo","env":"production"}}
   ```

### Hosting the front end somewhere else

The static site is a plain Vite build, so any static host works. In every case set **`VITE_API_URL`** to the
API origin, and add that host's URL to the API's **`CLIENT_ORIGIN`** (comma-separate several).

| Host | Build command | Publish dir | Notes |
|---|---|---|---|
| Netlify | `npm install && npm run build` | `client/dist` | add a `/*  →  /index.html  200` rewrite |
| Vercel | `npm install && npm run build` | `client/dist` | framework preset **Vite**; rewrites are automatic |
| Cloudflare Pages | `npm install && npm run build` | `client/dist` | SPA fallback is on by default |

The API can go on any Node host too (Railway, Fly, a VPS). It needs `MONGODB_URI`, `JWT_SECRET`,
`ADMIN_EMAIL`, `ADMIN_PASSWORD`, `CLIENT_ORIGIN`, `SERVE_CLIENT=false`, and `npm run start` from the repo
root. On a VPS, run it behind Nginx with `proxy_pass` to `127.0.0.1:5050` and let Certbot handle TLS.

### Two things to get right

- **CORS.** A browser error like *"No 'Access-Control-Allow-Origin' header"* means `CLIENT_ORIGIN` on the API
  does not exactly match the site's origin — scheme, host and port all count, and a trailing slash breaks it.
  `CLIENT_ORIGIN=*` allows any origin if you need to unblock yourself while testing.
- **Uploaded images.** The admin panel stores uploads as `/uploads/<file>` and the client prepends
  `VITE_API_URL`, so they are served by the API, not the static site. On Render's free plan that disk is
  ephemeral — uploads vanish on redeploy. Paste external image URLs (Cloudinary, imgbb, GitHub raw) into the
  image fields instead, or attach a persistent disk at `/opt/render/project/src/server/uploads` on a paid
  plan.

## 2B. One Docker service — Render (≈5 minutes)

1. Sign up at **https://render.com** and connect your GitHub account.
2. Rename `render.docker.yaml` to `render.yaml` and push (Render only reads `render.yaml`), then
   **New → Blueprint** and pick the `mdabufaysaljoy/portfolio` repo. Render proposes a Docker web service
   named `faysal-portfolio` on the free plan.
   *(Prefer doing it by hand? **New → Web Service** → same repo → Runtime **Docker** → Plan **Free** →
   Health check path `/api/health`. Everything else is in the Dockerfile.)*
3. Render asks for the variables marked `sync: false`. Fill them in:

   | Variable | Value |
   |---|---|
   | `MONGODB_URI` | the Atlas string from step 1.5 |
   | `ADMIN_EMAIL` | the email you want to sign in with |
   | `ADMIN_PASSWORD` | a strong password you choose now (**not** the demo one) |
   | `CLIENT_ORIGIN` | `https://faysal-portfolio.onrender.com` — the service URL Render shows you |

   `JWT_SECRET` is generated by Render automatically and kept across deploys. `NODE_ENV`, `PORT` and
   `JWT_EXPIRES_IN` come from `render.yaml`.
4. **Apply / Create**. The first build takes ~3–5 minutes (it installs dependencies and builds the client).
5. Open the URL. The seed runs on first boot: profile, 9 projects, 43 skills, experience, services,
   testimonials. Sign in at `/admin` with the email and password from step 3.

`autoDeploy: true` is set, so every push to `main` redeploys.

## 3. After the first deploy

- **Change the admin password** — Settings → Change admin password, or rotate `ADMIN_PASSWORD` in Render.
  The value in `server/.env.example` and the README is a local demo credential and is public.
- **Edit your content** at `/admin`: add live URLs and cover images to projects, update the hero, stats and
  social links, change theme colours.
- **Custom domain** — Render → Settings → Custom Domains. Add the CNAME it gives you at your registrar;
  TLS is issued automatically. Then update `CLIENT_ORIGIN` to the new domain (on Option A, add it to the
  *API* service and point it at the *site's* domain).

## Things to know about the free plan

- **The service sleeps after ~15 minutes idle** and takes ~30 seconds to wake on the next request. Fine for a
  portfolio; $7/month (Starter) removes it. Don't use an external pinger — Render's terms disallow it.
- **On Option A the static site never sleeps**, so the page always loads instantly; the first API call after
  idle still waits for the API to wake.
- **The container filesystem is ephemeral.** Images uploaded through the admin panel (`/uploads`) are lost on
  redeploy. Use image URLs (Cloudinary, imgbb, GitHub raw) in the admin fields, or attach a persistent disk at
  `/app/server/uploads` on a paid plan.
- **The database is not ephemeral** — content you edit in the admin panel lives in Atlas and survives deploys.
- If `MONGODB_URI` is wrong or Atlas blocks the IP, the service **fails to start with a clear log message**
  instead of silently running on a throwaway file store. Check Render → Logs.

## Verifying a deploy

```bash
curl https://<your-service>.onrender.com/api/health
# {"data":{"ok":true,"driver":"mongo","env":"production"}}
```

`driver` must read `mongo`. Anything else means the database is not connected.

## Local production check

Single-service, exactly as Option B runs it:

```bash
docker compose up -d --build     # app + MongoDB on https://md-mushikur-rahman-samir.onrender.com
```

Split, exactly as Option A runs it — API only on 5050, SPA preview on 4173:

```bash
SERVE_CLIENT=false npm run start -w server
```

```bash
VITE_API_URL=http://localhost:5050 npm run build && npm run preview -w client
```

`CLIENT_ORIGIN` in `server/.env` must include `http://localhost:4173` for that second command to work.
