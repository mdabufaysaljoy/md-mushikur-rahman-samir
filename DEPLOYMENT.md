# Deploying to Render + MongoDB Atlas

One Docker web service on Render serves both the API and the built React site, with the database on a free
MongoDB Atlas cluster. Total cost: **$0** on the free tiers.

Everything in this repo is already prepared for it: `Dockerfile` (multi-stage build), `render.yaml`
(Render Blueprint) and `/api/health` for health checks. The image was built and tested locally against a real
MongoDB before this guide was written.

---

## 1. Database — MongoDB Atlas (≈5 minutes)

1. Sign up at **https://www.mongodb.com/cloud/atlas/register**.
2. **Create a cluster** → *M0 Free*. Pick the region nearest your visitors (Mumbai `ap-south-1` or
   Singapore `ap-southeast-1` for Bangladesh).
3. **Database Access** → *Add New Database User*:
   - Authentication: Password
   - Username: `portfolio`
   - Password: click *Autogenerate* and **copy it** — you need it in step 5.
   - Role: *Read and write to any database*
4. **Network Access** → *Add IP Address* → **Allow access from anywhere** (`0.0.0.0/0`).
   Render's free plan has no fixed outbound IP, so an allowlist of specific IPs will block it.
5. **Clusters → Connect → Drivers** and copy the connection string. It looks like:

   ```
   mongodb+srv://portfolio:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```

   Replace `<password>` with the password from step 3, and insert the database name before the `?`:

   ```
   mongodb+srv://portfolio:YOUR_PASSWORD@cluster0.xxxxx.mongodb.net/faysal_portfolio?retryWrites=true&w=majority
   ```

   Keep this string — it is `MONGODB_URI` below. If the password contains `@ : / ? # [ ] %`, URL-encode it.

---

## 2. Web service — Render (≈5 minutes)

1. Sign up at **https://render.com** and connect your GitHub account.
2. **New → Blueprint**, pick the `mdabufaysaljoy/portfolio` repo. Render reads `render.yaml` and proposes a
   Docker web service named `faysal-portfolio` on the free plan.
   *(Prefer doing it by hand? **New → Web Service** → same repo → Runtime **Docker** → Plan **Free** →
   Health check path `/api/health`. Everything else is in the Dockerfile.)*
3. Render asks for the variables marked `sync: false`. Fill them in:

   | Variable | Value |
   |---|---|
   | `MONGODB_URI` | the Atlas string from step 1.5 |
   | `ADMIN_EMAIL` | the email you want to sign in with |
   | `ADMIN_PASSWORD` | a strong password you choose now (**not** the demo one) |
   | `CLIENT_ORIGIN` | `https://faysal-portfolio.onrender.com` — the service URL Render shows you |

   `JWT_SECRET` is generated by Render automatically and kept across deploys. `NODE_ENV`, `PORT` and
   `JWT_EXPIRES_IN` come from `render.yaml`.
4. **Apply / Create**. The first build takes ~3–5 minutes (it installs dependencies and builds the client).
5. Open the URL. The seed runs on first boot: profile, 9 projects, 43 skills, experience, services,
   testimonials. Sign in at `/admin` with the email and password from step 3.

`autoDeploy: true` is set, so every push to `main` redeploys.

---

## 3. After the first deploy

- **Change the admin password** — Settings → Change admin password, or rotate `ADMIN_PASSWORD` in Render.
  The value in `server/.env.example` and the README is a local demo credential and is public.
- **Edit your content** at `/admin`: add live URLs and cover images to projects, update the hero, stats and
  social links, change theme colours.
- **Custom domain** — Render → Settings → Custom Domains. Add the CNAME it gives you at your registrar;
  TLS is issued automatically. Then update `CLIENT_ORIGIN` to the new domain.

## Things to know about the free plan

- **The service sleeps after ~15 minutes idle** and takes ~30 seconds to wake on the next request. Fine for a
  portfolio; $7/month (Starter) removes it. Don't use an external pinger — Render's terms disallow it.
- **The container filesystem is ephemeral.** Images uploaded through the admin panel (`/uploads`) are lost on
  redeploy. Use image URLs (Cloudinary, imgbb, GitHub raw) in the admin fields, or attach a persistent disk at
  `/app/server/uploads` on a paid plan.
- **The database is not ephemeral** — content you edit in the admin panel lives in Atlas and survives deploys.
- If `MONGODB_URI` is wrong or Atlas blocks the IP, the service **fails to start with a clear log message**
  instead of silently running on a throwaway file store. Check Render → Logs.

## Verifying a deploy

```bash
curl https://<your-service>.onrender.com/api/health
# {"data":{"ok":true,"driver":"mongo","env":"production"}}
```

`driver` must read `mongo`. Anything else means the database is not connected.

## Local production check

```bash
docker compose up -d --build     # app + MongoDB on http://localhost:5050
```
